# Hagenberg Thesis Development Directory

This directory is exclusively used for developing and building the `HagenbergThesis` package.
Typical package users will probably find no relevant information here.
For the general workflow of contributing (issues, pull requests, automated checks), see [CONTRIBUTING.md](../CONTRIBUTING.md).

## What You Find Here

`/dev` is the development directory for the [HagenbergThesis](https://github.com/Digital-Media/HagenbergThesis) package. It contains the following in the respective directories:

- `texmf`: Master style files, classes, and bibliography for the package. Note that, during development, only the central versions of these files are used.
- `ctan`: Distribution files for `hagenberg-thesis` submitted to [CTAN](https://ctan.org/pkg/hagenberg-thesis). Except for the package README (`ctan/hagenberg-thesis/README.md`) and the submission log (`ctan/_log/`), these files are generated by `make ctan`.
- `makefile`, `makefile-latex`: the build process (see below).
- `check-build.sh`: checks the results of a build (used by `make check`).
- `logs`: the LaTeX and Biber log files of each build (generated, ignored by git).

## How to Use

### Editing Styles and Classes

Make your edits to the style files and classes in `texmf/tex/latex/hagenberg-thesis/` (bibliography: `texmf/bibtex/bib/`). Changes are suggested by opening a pull request, see [CONTRIBUTING.md](../CONTRIBUTING.md).

Do *not* edit the version/date strings in `.sty`, `.cls` and `.bib` files.
These are marked `%%AUTO` and are automatically replaced with the current date during the build process (`make setdates`).

### Building and Distributing the Files

The `makefile` in this directory does the following:

- Updates the date fields in all package files before copying them to the various example documents in the `documents` directory.
- Runs a multi-pass `LaTeX` and `Biber`/`BibLaTeX` build using `latexmk` on each sample document in the `documents` directory to create the corresponding PDF files. Each document is always rebuilt completely.
- Packs each document into a ZIP file in the `download` directory for easy distribution and direct upload to [Overleaf](https://www.overleaf.com/).
- Builds the associated package manual.
- Assembles all files necessary for submission on CTAN (styles and classes, documentation, and examples) with the correct directory structure.

All these generated files are ignored by git on `main`; the automated build publishes them on the branch `build` (see [Continuous Integration](#continuous-integration)).

#### Preparing the Build Process for Windows

This requires a current [MiKTeX](https://miktex.org/) or [TeX Live](https://www.tug.org/texlive/) installation (with `latexmk` and `biber`) as well as `make` and `zip` executables, e.g., the GNU Win32 implementations:

1. Install **GnuWin Make** through one of the following options:
   1. Download and run the [GnuWin Make installer](https://gnuwin32.sourceforge.net/downlinks/make.php). This installs `make.exe` in `C:\Program Files (x86)\GnuWin32\bin`.
   2. Install using [Chocolatey](https://chocolatey.org/): `choco install make`.
   3. Install using [WinGet](https://learn.microsoft.com/windows/package-manager/winget/): `winget install GnuWin32.Make`.
2. Install **GnuWin Zip** through one of the following options:
   1. Download and run the [GnuWin Zip installer](https://gnuwin32.sourceforge.net/downlinks/zip.php). This installs `zip.exe` in `C:\Program Files (x86)\GnuWin32\bin`.
   2. Install using Chocolatey: `choco install zip`.
   3. Install using WinGet: `winget install GnuWin32.Zip`.
3. Add `C:\Program Files (x86)\GnuWin32\bin` to the Windows PATH using `Control Panel` ➔ `System` ➔ `Advanced system settings` ➔ `Environment variables`. If the tools are installed using Chocolatey or WinGet, they are automatically added to the path in the process.
4. To verify if the installation is working, start the `GitBash` shell (part of the Windows GIT installation) and run `which make` and `which zip`. This should show the location of the make executable, for example:

```shell
$ which make
/c/Program Files (x86)/GnuWin32/bin/make
$ which zip
/c/Program Files (x86)/GnuWin32/bin/zip
```

#### Preparing the Build Process for Linux and macOS

A current [TeX Live](https://www.tug.org/texlive/) installation (on macOS, e.g., [MacTeX](https://www.tug.org/mactex/)) including `latexmk` and `biber` is required. `make` and `zip` are usually available already; otherwise install them with the package manager (Linux) or the Xcode command line tools (`xcode-select --install`, macOS).

#### Running a Complete Build

Open a shell (`GitBash` on Windows) in directory `dev/` and simply enter
```shell
$ make
```

Relax and grab a coffee...

Note that the complete build (`make` or `make all`) also runs `make setdates` and `make ctan`, which **modify tracked files**: the date stamps in all `.sty`, `.cls` and `.bib` files, the version in the CTAN README (`ctan/hagenberg-thesis/README.md`), and the copies of `hgbreferences.bib` in the sample documents. These changes must not be committed; the automated build sets them after merging. Therefore:

- To **test changes**, build the documents and the manual without updating the date stamps, and check the results:
  ```shell
  $ make documents manual check
  ```
- If you ran the complete build, discard the changes of the build **after committing your own changes**, e.g., with `git restore .` (from the repository root).

#### Building Individual Parts

It is also possible to execute specific parts of the build process. Call `make` with the following arguments:

- `make inittex`: <br>
Adds `/dev/texmf/` as a TEXMF root directory in **MiKTeX** (using `initexmf`). This is only needed to compile the documents in `/documents/` directly (e.g., in a TeX editor) with the package files in `/dev/texmf/`; the build via `make` copies the package files into the document directories anyway. Note that this is not executed during a normal (full) `make`. For **TeX Live**, see [Using the Package Files with TeX Live](#using-the-package-files-with-tex-live).
- `make uninittex`: <br>
Unlinks `/dev/texmf/` as a TEXMF root directory in MiKTeX. This is needed for building documents in `/documents/` from global `hagenberg-thesis` package files installed in the local LaTeX installation (distributed via CTAN).
- `make setdates`: <br>
Sets the version number to the current date in all `.sty`, `.cls` and `.bib` files.
- `make documents`: <br>
Builds all sample documents in the `documents` directory and creates their ZIP files in the `download` directory.
- `make <DocumentName>`: <br>
Builds a single sample document. Replace `<DocumentName>` with the respective document's directory name. E.g., use `make HgbThesisTutorialDE` to build the thesis tutorial document or `make HgbArticle` to build the article document.
- `make manual`: <br>
Builds the package manual.
- `make ctan`: <br>
Collects all files required for the CTAN distribution (in directory `ctan`). This requires the manual and the tutorials to be built first.
- `make check`: <br>
Checks the results of a previous build (see [What Is Checked](../CONTRIBUTING.md#what-is-checked)): all PDF files exist, the LaTeX and Biber log files (kept in `dev/logs/` during each build) contain no errors or problematic warnings, and all PDF files are PDF/A-2b compliant.
The PDF/A check requires [veraPDF](https://verapdf.org/software/): use `make check VERAPDF=/path/to/verapdf` if it is not on the path, or `make check VERAPDF=skip` to skip it.
- `make showsetup`: <br>
Shows the directories and settings used by the makefile.

#### Using the Package Files with TeX Live

The TeX Live counterpart of `make inittex` is an additional TEXMF tree. From directory `dev/`, run:

```shell
$ tlmgr conf auxtrees add "$(pwd)/texmf"      # use the package files in /dev/texmf/
$ tlmgr conf auxtrees remove "$(pwd)/texmf"   # undo (counterpart of 'make uninittex')
```

If `tlmgr` is not available (e.g., TeX Live packages of a Linux distribution), set the environment variable `TEXMFHOME` to the absolute path of `/dev/texmf/` instead (e.g., `export TEXMFHOME=/path/to/HagenbergThesis/dev/texmf` in the shell before running LaTeX). Note that this replaces your personal TEXMF tree while it is set.

### Continuous Integration

The GitHub Actions workflow [`.github/workflows/build.yml`](../.github/workflows/build.yml) uses the same makefiles in a current TeX Live (Docker image `texlive/texlive:latest`):

1. It installs the required tools (`make`, `zip`, `git`, Java for veraPDF).
2. It runs `make all`, i.e., the complete build including the date stamps and the CTAN bundle.
3. It installs the current version of [veraPDF](https://verapdf.org) and runs `make check`. The results are shown as a table in the job summary of the run.
4. It uploads the PDFs and log files as an artifact of the run (kept for 14 days).
5. Only after a push to `main` (i.e., merging a pull request): it publishes the results to the branch `build`.

The workflow runs

- for every **pull request** to `main`. The pull request should only be merged if this check passes.
- **manually** for any branch (*Actions* ➔ *Build and check documents* ➔ *Run workflow*), e.g., to build the PDFs of a branch without a pull request.
- after every **push to `main`**, which publishes the results.

#### The Branch `build`

The branch `build` contains the result of the latest build of `main`: the sources of `main` with the current date stamps plus all generated files (PDFs, ZIP files, CTAN bundle). It consists of a **single commit without history** (`git checkout --orphan`) that is force-pushed on every build. Thus, clones of the repository only contain the latest set of generated files, and the repository does not grow with every build.

- The PDF previews, ZIP downloads and Overleaf links in the main README point to this branch.
- The CTAN bundle of a release is taken from this branch (`dev/ctan/hagenberg-thesis.zip`).
- Never commit to this branch directly; it is overwritten by the next build.

### Testing Changes

To test and review your changes, build the documents locally (see [Running a Complete Build](#running-a-complete-build)) and open the resulting PDF files, e.g., `documents/HgbThesisTutorialEN/main.pdf` or `documents/HgbThesisTutorialDE/main.pdf`, or download the PDFs built for a pull request from its workflow run (see [CONTRIBUTING.md](../CONTRIBUTING.md#testing-a-pull-request)).
The PDFs can then be tested and evaluated (e.g., for PDF/A and included metadata). Note that the package's required `.sty`, `.cls` and `.pdf` files are only copied temporarily to the document directories during the build process and subsequently removed again. Only an up-to-date copy of the common bibtex file `hgbreferences.bib` remains in the document directory, because it cannot be distributed through CTAN.

Note that the zip'ed documents in directory `download/` all contain local copies of the current `.sty`, `.cls` and `.pdf` package files. Thus these documents, once expanded, can be readily re-compiled in stand-alone mode.

### GIT Repository Cleanup

Up to 2026, the generated files (PDFs, ZIP files, CTAN bundle) were committed to `main` with each update, so the history of `main` contains many versions of these binary files. Since the automated build publishes them on the branch `build` (see above), the history no longer grows. To purge the old files from the repo's history, do the following:

- Get [BFG Repo Cleaner](https://rtyley.github.io/bfg-repo-cleaner/) (a single Java JAR file, referred to as ``bfg.jar`` below).

Use the shell (`Git Bash`) to perform the following steps:

- ``$ git clone --mirror https://github.com/Digital-Media/HagenbergThesis.git`` (this creates a bare repo in folder ``HagenbergThesis.git``)
- Make a backup copy of ``HagenbergThesis.git`` to be safe.
- ``$ java -jar bfg.jar --delete-files 'main.pdf,hagenberg*.zip,Hgb*.zip,Manual.zip' HagenbergThesis.git``
- ``$ cd HagenbergThesis.git``
- ``$ git reflog expire --expire=now --all && git gc --prune=now --aggressive``
- ``$ git push``

Cleaning reports can be found in the ``HagenbergThesis.git.bfg-report`` folder.

Finally, make a **fresh checkout** (clone) from ``https://github.com/Digital-Media/HagenbergThesis.git`` to avoid local garbage being pushed again!
